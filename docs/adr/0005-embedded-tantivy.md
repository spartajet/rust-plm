# ADR-0005 全文检索内嵌 tantivy（不引入 Elasticsearch）

- 状态：已接受（2026-11-11）
- 关联需求：RPT-01/03/06（千万级 P95<200ms、5s 近实时）、F3（轻量部署）

## 背景

全文检索备选：Elasticsearch（部署重：JVM、多 GB 内存、独立集群——违背 2C4G 单机承诺）；Meilisearch（独立进程，内存占用偏高，中文分词一般）；tantivy（Rust 内嵌库，单机性能强，配 jieba-rs 中文分词成熟）。

## 决策

内嵌 tantivy：进程内索引器 + 按对象类型分 shard（索引隔离、可独立重建）；中文分词 jieba-rs + 同义词表（配置中心维护，热生效）；**权限过滤内嵌**——检索结果按用户权限位图过滤（预计算角色→对象集 bitset，避免查后过滤的越权泄露）。索引更新走事件订阅（对象写入 → Outbox → 索引任务），近实时 <5s。

## 后果

- ✅ 零额外部署（F3）；单机千万文档关键词检索 P95<200ms 可达；
- ⚠️ 索引与库的最终一致（对账修复任务，附件 B §7.2 已列）；
- ⚠️ 分布式检索不支持——单机场景够用；未来多副本时 tantivy 快照可随盘复制，暂不设计。
