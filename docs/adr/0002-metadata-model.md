# ADR-0002 元数据驱动对象模型：JSONB + 高频属性提升列 + 在线 DDL

- 状态：已接受（2026-11-11）
- 关联需求：AGL-01/02（在线建模、配置热生效）、A2（90% 免代码）

## 背景

"类型/属性/关系运行期可配置"（学 Aras）是敏捷卖点的技术根基。备选：①纯 EAV 表（行存属性）——查询join爆炸、类型弱；②每类型动态建表——DDL 频繁、迁移困难；③单一大 JSONB 列——简单但高频筛选慢。

## 决策

三段式存储：**系统属性物理列 + 自定义属性 `attrs JSONB`（GIN 索引）+ 高频筛选属性可"提升为列"**（管理员在配置中心标记后，由系统执行在线加列 `ALTER TABLE ... ADD COLUMN ... NOT NULL DEFAULT`，锁表 <1s，PostgreSQL 11+ 不重写表）。类型/属性/关系定义存元数据表，对象 CRUD 由 `core-model` 统一解释执行（动态 SQL 由 QueryBuilder 生成，sqlx 运行期绑定）。

## 后果

- ✅ 新类型零代码、改属性即存即用（JSONB）；列表页 P95 达标（高频列 + btree）；
- ✅ 提升/回退为可逆操作，元数据记录列与 JSONB 的同步策略（提升时回填、写入双写直至稳定）；
- ⚠️ 动态查询无法用 sqlx 编译期校验——动态层用运行期校验 + 全量集成测试兜底；
- ⚠️ 需要设计收尾验证：**最小原型验证 GIN vs 提升列的筛选性能与在线 DDL 锁行为**（见概设 §9 验证计划 V-1）。
