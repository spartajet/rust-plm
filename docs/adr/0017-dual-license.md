# ADR-0017 开源协议：AGPL-3.0 双许可（≤30 用户免费，超出商业收费）

- 状态：已接受（2026-11-11，用户选型批次 6：**开源 + 30 用户以上商业使用收费**）
- 关联需求：SYS-05（License 管理）、PLG-05（插件市场）、商业模式 C1–C3

## 决策

- **Community 版**：AGPL-3.0 开源——自由使用/修改/自部署，**≤30 命名用户免费商用**（含 SaaS，但对外提供服务须遵守 AGPL 开源义务）；30 用户上限由 SYS-05 License 计量闸门执行（超限降为只读 + 升级引导，不阻断数据安全）。
- **Enterprise 商业许可**：>30 用户、闭源集成/二次开发闭源分发、专属支持——按用户数/模块订阅或买断。
- **SDK 例外（Apache-2.0）**：`plm-plugin-sdk`、`plm-connector-sdk`、wit 世界定义、公开 REST API 客户端均以 Apache-2.0 独立发布——第三方插件/连接器开发者**不受 copyleft 传染**，优先保插件生态规模。
- 合规：CI 中 cargo-deny 许可检查——主程序禁引入与 AGPL 冲突的许可；SDK crate 禁引入 GPL 系依赖（保持其可 Apache 发布）。
- 随包分发 LICENSE / NOTICE / DUAL-LICENSING 三文件；商业条款由合同承载。

## 后果

- ✅ 开源获客与信任（信创/小微友好）+ AGPL 网络条款天然保护商业转化（SaaS 白嫖需开源，闭源需付费）；
- ✅ 参考 MinIO/iText 等成熟双许可先例；
- ⚠️ AGPL 对部分大企业采购有心理阻力——销售话术引导至商业许可（这正是转化路径）；
- ⚠️ 30 用户计量需防绕过（命名用户定义、共享账号检测写入 SYS 审计）；
- ⚠️ 社区贡献需 CLA（贡献者授权协议）保证双许可可执行——仓库加 CLA 机器人，V1.5 前落实。
