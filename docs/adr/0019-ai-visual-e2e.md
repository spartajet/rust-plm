# ADR-0019 开发流程：AI agent 视觉交互自测（开发期实践，非产品能力）

- 状态：已接受（2026-11-11；同日澄清定位：**这是本项目开发过程的测试手段，产品本身不包含该能力**）
- 关联：需求文档 §7.7 注、技术选型说明书 §2A

## 背景

本项目研发由 AI coding agent 主导（含前端开发）。UI 改动的"看起来对不对"传统上靠人工打开浏览器目检——在 agent 开发模式下这是最大的人工瓶颈。多模态视觉模型（VLM）已能可靠判断截图中的布局/组件/交互结果，可以让 agent **自己看自己改的界面**。

## 决策

开发期采用 **AI agent 视觉交互自测闭环**：

1. agent 完成前端改动 → 本地/容器启动 dev server；
2. 通过 Playwright（或浏览器自动化 MCP 工具）执行目标操作并**截图**；
3. 截图交 **VLM（视觉模型）判断**：页面是否按预期渲染、操作结果是否正确（断言依据写入任务描述或验收锚点）；
4. 不符合 → agent 继续迭代；符合 → **将验证过的行为固化为 Playwright 脚本用例**（进入产品 CI 的 L5 层）。

约定：
- **过程 vs 资产**：视觉自测是开发过程（不进产品 CI、不对客户承诺）；Playwright 脚本与像素基线才是测试资产；
- 每轮自测产物（截图 + VLM 判断理由）归档进 PR/会话记录，供人工抽查；
- 工具不绑定：Playwright 截图 + 任意 VLM（GLM-4V/Qwen-VL/GPT-4o），或 MidScene.js 等视觉 agent 框架加速，按开发环境可用性选择；
- 人工角色：抽查 agent 自测结论、验收视觉设计质量（审美与产品判断仍归人）。

## 后果

- ✅ agent 前端开发从"盲改"变"看着改"，迭代轮次显著减少；人工目检前移为抽查；
- ✅ 自测结论即时沉淀为回归用例，测试资产随开发同步增长；
- ⚠️ VLM 判断有误判率——关键业务正确性仍以 L1–L3 代码断言为准，视觉自测只回答"界面呈现"问题；
- ⚠️ 无头环境截图与真实浏览器渲染偶有差异——以 Playwright 标准浏览器上下文为准。
