# ADR-0003 BOM 存储：边表 + 闭包表双结构

- 状态：已接受（2026-11-11）
- 关联需求：BOM-06（10 万行展开 <1s）、F1

## 背景

BOM 展开有四种读法（单层/全量/到级/尾级）+ 反向 Where-used。纯递归 CTE 在 10 万行、深层级时性能不稳且无法并行；邻接表无法 O(1) 回答"用在哪儿"。

## 决策

双结构：`bom_edge`（版本化的单层父子边，行级属性）+ `bom_path`（闭包表：ancestor→descendant×depth，物化全路径）。**读路径全部走闭包表**（全量展开/Where-used 均为索引扫描，无递归）；**写路径在 BOM 版本提交时做图 diff，增量维护闭包表**（后台任务，同一事务内完成）。循环引用检测 = 写入前反向可达性检查（查 `bom_path` 即可，O(路径长)）。

## 后果

- ✅ 10 万行展开 = 一次索引扫描 + 结果集聚合，<1s 可承诺（F1）；
- ✅ 展开可按子树分片并行（rayon）进一步加速；
- ⚠️ 存储放大（闭包行数 ~O(边×平均深度)）——10 万行 BOM 预估闭包 <千万行，PostgreSQL 分区表可承受；超出后按 parent 版本分区归档；
- ⚠️ 闭包维护的正确性是关键——**最小原型验证：10 万行随机 BOM 的构建/改版/闭包增量维护耗时与正确性（对拍递归 CTE）**（见概设 §9 验证计划 V-2）。
