# ADR-0001 单体模块化架构（Modular Monolith，不做微服务）

- 状态：已接受（2026-11-11）
- 关联需求：F2（2C4G ≥50 并发）、F3（轻量部署）、C2（零专职 IT 运维）

## 背景

PLM 是强事务系统（对象+文件+流程+索引联动），调用链深；目标客群小微制造业只有一台 2C4G 服务器，无运维能力。微服务带来部署复杂度（注册中心/网关/多库）与分布式事务代价，收益（独立扩展、多语言）在本场景完全用不到。

## 决策

采用**单体模块化**：一个 `plm-server` 二进制 + 一个 PostgreSQL；模块边界以 Cargo crate 强制（核心域 crate 之间只经公开 trait/接口依赖，mod-* 只依赖 core-*，反向禁止）；未来确需拆分时以 crate 为单位外置。

## 后果

- ✅ 一条命令部署、一个进程运维；Rust + tokio 单体支撑数百并发绰绰有余（F2）；
- ✅ 事务一致性简单（单库 ACID）；
- ⚠️ 需要纪律：crate 依赖方向由 CI（cargo-deny/自定义检查）锁定，防止演化成大泥球；
- ⚠️ 单进程内故障隔离有限——插件（ADR-0006）与文件转换（子进程池）单独做了隔离，其余模块以 panic=abort + systemd/compose 重启自愈兜底。
