# RustPLM 需求符合度深度评审

> 评审基准：《产品需求文档 v1.1》（130+ 需求，20 模块）；对照实现：main @ 增量17 + 部署文档（后端 151 测试 / 前端 24 / e2e 26 / Playwright 9，全部绿）。
> 评审方法：PRD 逐模块逐条 vs 代码/测试实证（grep + 集成测试 + e2e），不确定项全部真库/源码抽查核实。
> 评级：✅ 实现且有测试钉 · 🟡 部分（核心在、附属缺）· ⬜ 未实现 · 🔵 仅文档/裁定（计划内后置）。

---

## 一、总评

**数据引擎层（LCS/BOM 引擎/COD/权限/事件外投）达成率高、质量过硬；产品化壳层（检索/审计/预览/待办/报表/批量导入）是主要欠账。**

- 17 个增量的主线选择正确：MVP 数据层 P0 核心（生命周期状态机、BOM 闭包引擎、COD 并发取号、RBAC+ABAC、Outbox 事件）全部落地且每个都有可证伪测试钉；性能有 V-1/V-2 实测背书（BOM 10 万行展开 42ms，余量 23×）。
- 但以 §8「MVP 即面向小微可售卖」的口径审视，**产品壳层的 P0 缺口集中在四类**：①SYS-01 审计日志（合规红线）②RPT-01/03 全局搜索与全文检索（tantivy 选型未接线）③WF-03 统一待办中心 UI + WF-05 超时催办（审批入口缺失——审批全靠 IM 卡片/Web API）④BOM/DOC 的编辑与预览 UI（BOM 只有 API 无编辑界面、图纸无在线预览只有下载）。
- 测试文化达标且超出一般水准（151 测试、终审文化、变异实证、对账台账），但 TQ-01 行覆盖率未量测、TQ-02 OpenAPI 契约快照未建。

## 五、缺口优先级排序（建议后续增量）

**P0-A（MVP 可售卖硬欠账）**
1. **SYS-01 审计日志**：append-only 审计表（登录/查看/下载/修改/审批/配置变更）+ 检索 + 导出——合规红线，且下载审计是文件受控的闭环要件

3. **RPT-01 全局搜索框 + RPT-03 tantivy 接线**（属性+文件名起步，正文抽取 V1.0）
4. **BOM 编辑 UI**（结构树增删改+行属性）+ BOM-07 汇总报表（用量/自制外购聚合 SQL 已有引擎）
5. **DOC-05 在线预览**（PDF/图片直开+水印起步；DWG→PDF 转换服务评估）
6. **防爆破/密码策略**（登录限流+锁定+SYS-04 最小参数中心）

**P0-B（第二梯队）**
7. INT-04①②（通讯录同步+扫码登录——IM MVP 收口，需企业凭证）
8. AGL-05 模板包导出导入+AGL-09 实施向导（7 天上线承诺）
9. DOC-03 检入检出+DOC-11 批量导入

**已按裁定后置（非欠账）**：EC 全模块（V1.0 首项）、FA/AI/PLUGIN/VIS/CAPP/PM/RQM（V1.5+）、IM 真实凭证联调（用户指令）、属性映射码/历史码映射（COD 尾）、PART 类型模板差异化。
