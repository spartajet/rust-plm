> 分支：`feat/doc12-links`；**迁移 0020（core-model）**：obj_link 泛化关联表（kind 区分未来 BOM/变更/项目）；无新 crate。

## 设计裁定

### D1 关联表（泛化）
`obj_link(id uuid PK, from_id uuid NOT NULL REFERENCES cm_object(id), to_id uuid NOT NULL REFERENCES cm_object(id), kind text NOT NULL, created_by uuid, created_at timestamptz DEFAULT now(), UNIQUE(from_id, to_id, kind))`——方向语义：from=文档、to=物料（kind="doc_part"）；未来 EC/Project 加 kind。双侧索引（from_id/to_id）支撑双向追溯。环无意义（kind 域内 from/to 类型不同）但自关联（from=to）拒绝。

### D2 端点（ABAC 双端越级 404——关联操作任一端越级即 404 不泄露）
- `POST /api/v1/links` body `{from_no, to_no, kind:"doc_part"}`（docs:write）→ 201 `{id}`；重复 → 409 `MDL-LINK-DUPLICATE`；自关联 400。
- `DELETE /api/v1/links/{id}`（docs:write）→ 204（无此关联 404）。
- `GET /api/v1/docs/{no}/links`（docs:read）→ `{items:[{link_id, obj_no, name, class_name}]}`（文档挂的物料；密级过滤 to 端）。
- `GET /api/v1/parts/{no}/links`（docs:read）→ 同构（物料挂的文档；密级过滤 from 端）。
- audit：`doc.link` / `doc.unlink`（object=from_no，detail 带 to_no/kind）。
- kind 白名单起步仅 doc_part（新增 kind 随域扩展——台账）。

### D3 前端（DocDetail「关联物料」卡）
- 卡片列表（编号/名称/分类/解除按钮）+「关联物料」对话框（parts/duplicates 名称搜索选件）。
- Parts 列表页不加详情——物料侧反查 API 就绪（e2e 钉），UI 随物料详情页（未建）后置。
