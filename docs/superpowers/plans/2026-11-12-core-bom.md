# 增量6：core-bom BOM 引擎 实施计划（含短设计）

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans（Native，既定）。

**Goal:** BOM 主线产品化——对象的 EBOM 结构管理（增删改行/单事务闭包增量维护/循环拒绝）、全量/尾级展开（NDJSON 流式）、Where-used 反查；权限沿用 docs read/write。

**短设计（Approaches）:** A（选定）**BOM 锚定业务对象**：bom_edge.parent_id = cm_object.id（版本=对象版本），闭包表 bom_path 由改边事务内增量维护（V-2 已验证 143ms/2000边）；B 独立 BOM 对象+独立版本链（PRD BOM-02 完整语义，后置增量——Revise 升版机制就位后再拆）；C 查询时递归 CTE 实时展开（V-2 实测 3x 慢于闭包，否）。

**Spec:** ADR-0003、概设 §3.3、PRD BOM-01/02/06/07、spikes/bom-spike（V-2 算法已对拍 100%）。

## Global Constraints

- 迁移 0009（core-bom）：bom_edge(parent uuid→cm_object, line_no, child uuid→cm_object, qty, attrs jsonb, PK(parent,line_no)) + bom_path(ancestor,descendant,depth,qty_path, PK(ancestor,descendant,depth)) + 快照唯一兜底索引
- 循环引用：加边 X→Y 前查 `bom_path(ancestor=Y, descendant=X)` 命中→拒绝 `MDL-BOM-CYCLE`(409)
- 展开流式 NDJSON（F1 性能承诺的 API 面）；`MDL-BOM-CYCLE`/`MDL-BOM-NOT-FOUND`
- 权限：expand/where-used=docs:read；lines 写=docs:write
- 数量语义：qty_path 累加（同 (anc,desc,depth) 多路径求和，与 CTE 对拍语义一致——V-2 已验证）
