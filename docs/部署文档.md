# RustPLM 部署文档

> 适用版本：增量17（2026-11）。单二进制 + PostgreSQL 18，一台 2C4G 小服务器跑全公司。
> 部署模型：**Docker Compose 单机**（推荐）/ 本地开发源码运行 / 前端三种接入方式。

---

## 1. 架构与组件

```
浏览器 ──HTTP(S)──▶ [前端静态资源/dist 或 vite dev]
                        │ 同源 /api（反代）或直连 :8080（CORS 已放开）
                        ▼
                 plm-server（Rust 单二进制，axum）
                        │ sqlx
                        ▼
                 PostgreSQL 18（唯一有状态依赖；迁移自动执行）
                 文件存储：本地卷 /data（内容寻址 SHA-256）
                 全文索引：/data/search（内嵌 tantivy；单实例目录锁，多实例第二实例 503 fail-closed）
```

- **单二进制** `plm-server`：内嵌全部迁移（启动自动执行，`_sqlx_migrations` 记账）+ 前端 API。
- **无 Redis/消息队列**：事件外投走 DB Outbox 轮询（ADR-0007），Webhook/IM 卡片内置。
- **健康检查**：`GET /healthz`（DB 可达性 + 元数据版本）。

## 2. Docker Compose 单机部署（推荐）

### 2.1 首次部署

```bash
git clone https://github.com/spartajet/rust-plm.git && cd rust-plm
docker compose up -d --build
# 首次构建约 5-10 分钟（Rust 全量编译）；之后增量缓存

# 健康
curl http://localhost:8080/healthz
# {"status":"ok","meta_version":...}

# admin 初始密码：首次启动随机生成并打印一次（docker compose logs plm | grep 密码）
# 也可显式指定（见 §4 PLM_ADMIN_PASSWORD）
```

### 2.2 compose 变量

| 变量 | 缺省 | 说明 |
|---|---|---|
| `HTTP_PORT` | `8080` | 宿主机映射端口 |
| `POSTGRES_PASSWORD` | `plmdev` | PG 口令（**生产必须改**） |
| `PLM_VERSION` | `dev` | 镜像 tag |

### 2.3 数据持久化

| 卷 | 内容 | 备份 |
|---|---|---|
| `plm-pgdata` | 全部业务数据（对象/物料/BOM/快照/事件） | `pg_dump` 定期备份 |
| `plm-files` | 上传文件内容（SHA-256 内容寻址，去重） | 卷快照 / rsync |

> 两者**必须同时备份**且时点对齐（文件按 hash 引用，独立可恢复——但对齐避免悬空引用窗口）。

### 2.4 升级

```bash
git pull && docker compose up -d --build
# 启动自动跑新增迁移（全仓全局唯一版本号，见 docs/migrations.md；只增不改）
# 回滚：回退镜像 tag；迁移文件只增不改设计下，旧版本代码可跑旧库（新列带缺省）
```

## 3. 环境变量全集（服务端）

`plm-server` 读两路环境变量：**无前缀** `DATABASE_URL`，及 **`PLM_` 前缀**业务配置（figment，不区分大小写）。

| 变量 | 必填 | 缺省 | 说明 |
|---|---|---|---|
| `DATABASE_URL` | ✓ | — | `postgres://user:pass@host:5432/db` |
| `PLM_DATA_DIR` | — | `data` | 上传文件根目录（容器内 `/data`） |
| `PLM_HTTP_PORT` | — | `8080` | 监听端口 |
| `PLM_MAX_UPLOAD` | — | `209715200`（200MB） | 上传体积上限（字节） |
| `PLM_ADMIN_PASSWORD` | — | 随机生成打印一次 | admin 初始密码（仅首建生效，幂等重跑不改） |
| `PLM_JWT_SECRET` | — | `data_dir/jwt.key` 文件复用 | JWT 签名密钥；**多实例部署必须显式设置**（各实例一致） |
| `PLM_IM_PROVIDER` | — | `none` | IM 卡片：`none`/`dingtalk`/`wecom`/`feishu` |
| `PLM_IM_WEBHOOK` | — | 空 | 群机器人 webhook 地址（钉钉含 access_token） |
| `PLM_IM_SECRET` | — | 空 | 钉钉加签密钥；**同时是回调验签密钥**——空则 IM 回调端点 503 关闭 |
| `PLM_IM_DOC_URL_TEMPLATE` | — | 空 | 卡片详情链接模板，`{obj_no}` 占位 |
| `PLM_IM_USER_MAP` | — | 空 | IM id→PLM username JSON：`{"im-ding-1":"zhangsan"}` |
| `PLM_SEARCH_SCAN_SECS` | — | `2` | 全文检索对账扫描周期秒（近实时 <5s；索引目录 `data_dir/search`） |

**令牌时效**（代码常量，未配置化）：access 15 分钟 / refresh 7 天；前端 401 自动 refresh 换发重放。

## 4. 前端部署（三种方式）

### 方式 A：反代同源（生产推荐）

前端 `npm run build` 产出 `dist/`，由 Nginx/Caddy 托管并把 `/api` 反代到 plm-server：

```nginx
server {
  listen 443 ssl;
  server_name plm.your.co;
  # TLS 证书（TLS 终止在反代——ADR-0014；plm-server 本身 HTTP）
  root /var/www/rustplm/dist;
  location / {
    try_files $uri $uri/ /index.html;   # SPA 路由回退
  }
  location /api/ {
    proxy_pass http://127.0.0.1:8080;
    proxy_set_header Host $host;
    client_max_body_size 200m;          # 对齐 PLM_MAX_UPLOAD
  }
}
```

前端构建时设 `VITE_API_BASE=""`（空=同源相对路径，走反代）：

```bash
cd frontend && npm ci && VITE_API_BASE="" npm run build
```

### 方式 B：浏览器直连 API（前后端分离/无反代）

后端 CORS 已放开（Bearer 头鉴权，CORS 不构成安全边界——裁定见 docs/migrations.md）：

```bash
cd frontend && npm ci
VITE_API_BASE=http://your-server:8080 npx vite --port 5173 --host 0.0.0.0
# 或构建：VITE_API_BASE=http://your-server:8080 npm run build && npx vite preview
```

> 本机开发提示：Windows 下 `localhost` 解析为 `::1`（单栈），后端仅绑 IPv4——直连地址用 `127.0.0.1`。

### 方式 C：vite dev 代理（本地开发）

```bash
VITE_API_PROXY_TARGET=http://127.0.0.1:8080 npx vite --port 5173
# 浏览器开 http://localhost:5173；/api 由 vite 代理转发
```

## 5. 本地开发（源码运行，无 Docker）

```bash
# 0) 前置：Rust stable + Node 18+ + PostgreSQL 18（本机服务）
# 1) 建库（迁移启动自动执行）
createdb plm   # 或 psql -c "CREATE DATABASE plm"

# 2) 起服务端
DATABASE_URL=postgres://postgres:root@localhost:5432/plm \
PLM_ADMIN_PASSWORD=dev-admin-123 \
cargo run -p plm-server
# 就绪日志：RustPLM 就绪 addr=0.0.0.0:8080

# 3) 起前端（另一终端）
cd frontend && npm ci
VITE_API_BASE=http://127.0.0.1:8080 npx vite --port 5173 --host 127.0.0.1

# 4) 登录 http://localhost:5173 → admin / dev-admin-123
```

### 测试

```bash
# 后端（真库集成测试，每测试独立临时库自动创建/销毁）
export TEST_DATABASE_URL=postgres://postgres:root@localhost:5432/postgres
cargo test --workspace

# 前端单测
cd frontend && npx vitest run

# Playwright 真链路（需后端 18095 + vite 5173 已起）
E2E_API_BASE=http://127.0.0.1:18095 npx playwright test
```

## 6. 迁移与版本管理

- 迁移启动**自动执行**，无需手工步骤；版本号全仓全局唯一（**新增迁移前必查 `docs/migrations.md` 注册表**）。
- **只增不改**纪律：已发布迁移文件禁止修改（存量库校验和比对会崩）；修正走新迁移。
- 当前迁移清单/Outbox payload 契约/部署裁定（REVOKE、reject 非对称）：见 [docs/migrations.md](migrations.md)。

## 7. 安全清单（生产上线前）

- [ ] `POSTGRES_PASSWORD` 改强口令；PG 不暴露公网（compose 内网即可）
- [ ] `PLM_JWT_SECRET` 显式设置（多实例一致）；`PLM_ADMIN_PASSWORD` 显式设置并首登后改密
- [ ] 反代 TLS 终止（Let's Encrypt）；`client_max_body_size` 对齐上传上限
- [ ] Webhook `secret` ≥8 字符（HMAC 强度）；IM 回调仅经各平台企业应用网关转发
- [ ] 角色最小化：admin 仅管理员；业务用户 editor/viewer；密级上限按人配置（缺省 0 fail-closed）
- [ ] 备份：`plm-pgdata` + `plm-files` 双卷定时备份（§2.3）
- [ ] 资源：2C4G 起步；PG `shared_buffers` 按机器调优（缺省可跑）

## 8. 故障排查

| 症状 | 排查 |
|---|---|
| `/healthz` 返回 `degraded` | DB 不可达：查 `DATABASE_URL`/PG 容器状态 |
| 登录 401 | admin 密码（首启日志）；JWT 密钥跨实例不一致（多实例须同 `PLM_JWT_SECRET`） |
| 上传 413/400 | 体积超 `PLM_MAX_UPLOAD`/反代 `client_max_body_size`；或图号重复（409） |
| Webhook 无投递 | 订阅 url 须 http(s)://、secret ≥8、topics ∈ 已知主题；死信排查 `GET /api/v1/sec/webhooks/dead` |
| IM 无卡片 | `PLM_IM_PROVIDER/WEBHOOK/SECRET` 三项齐配（none=不发）；`im_card_log` 表看 attempts/error |
| 自动编码 400 "未配置编码规则" | 类型/分类未配 `cod_rule`；预览端点 `GET /meta/types/{code}/cod-preview` 验证 |
| Windows 本机偶发连接重置 | 安全软件干扰环回——前端用直连模式（方式 B）+ 后端池已带 idle_timeout 回收 |

## 9. API 文档与端点清单

- OpenAPI：`GET /api/docs/openapi.json`；Scalar UI：`/api/docs`（豁免鉴权）。
- 端点总览（鉴权全 Bearer）：

| 组 | 端点 | 权限 |
|---|---|---|
| 认证 | POST /auth/login、/auth/refresh | 免 |
| 图文档 | POST/GET /docs、GET /docs/{no}、/file、/versions、POST submit/approve/reject/release/obsolete/revise（动作可带 `{"comment":...}`）、POST /docs/batch-approve（批量批准，逐项结果，上限 50） | docs:read/write/approve |
| 待办中心 | GET /todos?box=todo\|done\|mine（待办/已办/我发起；ABAC 密级过滤） | docs:read |
| 全局搜索 | GET /search?q=…[&type=drawing\|part&page&size]（聚类/钻取；tantivy 内嵌索引+jieba 分词；ABAC 密级过滤） | docs:read |
| BOM | POST /boms/{no}/lines；GET /boms/{no}/expand（?major=N as-of）、/where-used（?asof=1） | write / read |
| BOM 编辑/汇总 | GET /boms/{no}/lines（富行，?major=N 快照行）、GET /boms/{no}/summary（用量/分类汇总，?format=csv 下载） | read |
| 在线预览 | GET /docs/{no}/preview（MIME 白名单 inline：pdf/png/jpeg/gif/webp；其余 415） | read |
| 物料 | POST /parts、GET /parts、/parts/duplicates、GET /classes | write / read |
| 编码 | GET /meta/types/{code}、/cod-preview；PUT /meta/types/{code}/flow-tier（body `{tier?, require_comment?}`——意见必填开关同端点配置） | 认证 / approve |
| 管理 | POST/GET /sec/users、POST/DELETE /sec/users/{u}/roles/{r}、GET /sec/roles | sec:manage |
| 安全参数 | GET /sec/params、PUT /sec/params/{key}（密码策略/锁定阈值与时长；修改 audit 留痕） | sec:manage |
| 模板包/向导 | GET /meta/template/export\|starter、POST /meta/template/import（dry_run/merge）；GET /meta/impl-checklist、POST …/{step}/complete | sec:manage / 认证 |
| Webhook | POST/GET /sec/webhooks、DELETE /{id}、GET /dead?page&size | sec:manage |
| IM 回调 | POST /im/actions（HMAC） | 免（验签+映射） |
| 健康与文档 | GET /healthz、/api/docs* | 免 |
