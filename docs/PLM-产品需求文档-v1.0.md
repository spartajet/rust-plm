## 1. 产品概述

### 1.1 背景与市场机会

PLM（Product Lifecycle Management，产品生命周期管理）是制造业研发数字化的核心系统，承接从需求、概念设计、详细设计、工艺、试制到量产与退市的全过程数据与流程管理。国内市场当前格局：

- **国际厂商**（Siemens Teamcenter、PTC Windchill、达索 ENOVIA、开源系 Aras Innovator）功能全面但实施重、费用高、本土响应慢，基本不服务小微；
- **国内传统厂商**（用友/智石开、金蝶云星空、华天软件 InforCenter、开目、CAXA 数码大方、鼎捷、思普、三品等）在 CAD 集成、工艺、ERP 协同方面各有积累，但普遍基于 Java/.NET 传统技术栈，架构重、资源占用大、实施周期以"月/年"计，目标客群以中型以上企业为主；
- **小微赛道新势力**：橙色云智橙 PLM（SaaS 云原生 + 云 CAD，主打"小轻快准"）、开目 OpenVelo（SaaS PLM）等已验证"中小微用得起 PLM"的市场存在，但普遍是云端 SaaS 形态，对图纸保密敏感的小微制造业覆盖不足，且性能与集成深度受多租户架构限制；
- **行业痛点**：业界普遍认为约 90% 的 PLM 项目达不到"单一可信数据源"的预期；对小微制造业，痛点更原始——**图纸在共享盘/个人电脑、BOM 在 Excel、变更靠吼、没有专职 IT 与标准化员、总预算常常不足 5 万元/年**（详见附件调研报告）。

**机会**：用 Rust 重写 PLM 底座，为**制造业中小微企业**提供"私有部署的价格、SaaS 的开箱即用"：在同等功能覆盖下提供数量级的性能/资源优势（一台 2C4G 小服务器即可跑起来）、"7 天可上线"的敏捷实施能力，并以**插件化 + FA 商城选型直连 + 全栈设计工具集成（机械/电气/电子）+ AI 助手**形成对小微客群独特、竞品难以快速复制的产品纵深。

### 1.2 产品定位

> **一套安装即用、配置即灵、快到没有存在感的中小微制造企业 PLM。**

- 面向离散制造**中小微企业**（非标自动化设备、机电一体化、电子硬件、精密五金、汽配二三级、医疗器械初创等：10–300 人为主力，3–10 人创客团队用 Starter 模式）；
- 对标国内主流 PLM 的功能底座（图文档 + 物料 + BOM + 流程 + 变更 + 设计工具集成 + 轻项目管理），但**处处为小微做减法与默认值优化**（见 3.9 节）；
- 差异化竞争点：Rust 单体高性能内核（一台小服务器全公司使用）+ 全链路配置化 + 小微行业模板包 + **插件化平台** + **FA 工业品商城选型直连** + **机械/电气/电子全栈设计工具集成** + **钉钉/企微/飞书深度协同** + **AI 助手**。

### 1.3 核心价值主张（产品宪法）

### 1.4 目标客户与角色

**客户画像（按工信部中小微企业划型标准界定目标客群）**：
1. **主力客群**：20–300 人的小型/微型离散制造企业——非标自动化设备、机电一体化装备、电子硬件/智能硬件、精密五金模具、汽配二三级、医疗器械初创等。特征：有 1–20 名设计人员、图纸分散在个人电脑和共享盘、BOM 靠 Excel、老板亲自管审批、**无专职 IT 与标准化员、对价格敏感、对"慢和复杂"零容忍**；
2. **种子客群**：3–20 人的创客型/初创硬件团队——用 Starter 模式（免配置向导式初始化）起步，随成长升级；
3. **不主攻**（但不排斥）：中型以上企业整厂级 PLM——以单模块（图文档/BOM）部门级切入。

**小微角色画像（典型"一人多角"，系统必须适配而非要求企业配齐全角色）**：

| 角色（可为同一人兼任） | 关注点 | 高频操作 |
|---|---|---|
| 老板/总经理（兼审批人） | 手机上快速批、心里有数 | 钉钉/企微/飞书卡片审批、看板 |
| 技术负责人/总工（兼标准化） | 一物一码、图纸受控、别出事故 | 物料审批、发布审批、变更把关 |
| 设计工程师（机械/电气/电子） | 顺手的工具集成、少填表 | CAD/EDA 检入检出、BOM 编辑、FA 选型 |
| 工艺/采购（常为兼职角色） | 选型有据、买得对买得快 | FA 商城选型入库、外购件属性确认 |
| 系统管理员（常由技术负责人兼任） | 别让我维护服务器 | 极简配置、一键备份、体检报告 |

> **系统角色（RBAC 基础角色集）**：小微默认模板预置以上 5 个角色的"合并版权限包"，开箱即用；成长模式下可启用细粒度角色（项目经理、标准化员、质量员、集成账号等），见 6.1。

## 3. 核心设计思想

### 3.1 单一数据源（Single Source of Truth）

所有产品数据（物料、图纸、BOM、工艺、变更、项目交付物）**只存一份**、只在一处维护、由状态与权限管控引用。任何下游（ERP/MES/OA/报表）都从本系统订阅或拉取，禁止手抄。这是 PLM 的第一性原理，也是行业 90% 项目未达预期的分水岭——**本产品所有功能设计必须服务这一原则**。

### 3.2 统一业务对象模型（Everything is a Business Object）

学习 Aras/Teamcenter 的元数据驱动思想：

- 系统内置**对象类型（Type）**机制：物料、图文档、BOM、变更单、项目、工艺路线……都是"业务对象"；
- 每个类型由**系统属性（ID/版本/状态/密级/创建人…）+ 自定义属性（字段/校验/字典）**构成；
- 对象之间通过**关系（Relationship）**连接：装配、引用、更改、签审、关联项目……；
- 类型、属性、关系、表单、列表视图**全部可在运行期由实施顾问配置**，不写代码、不重启。

> 这是"敏捷"卖点 A2 的技术根基：客户业务变化 → 改配置 → 立即生效。

### 3.3 以 BOM 为主线（BOM-Centric）

从设计 BOM（EBOM）→ 工艺 BOM（PBOM）→ 制造 BOM（MBOM）的演进链路是制造企业研发数字化主线。系统必须支持：多视图、视图间结构映射与追溯、版本对比（Diff）、有效性（日期/批次/序列号）、汇总报表（自制/外购分类汇总）。物料（Part）与文档（Document）双对象分离、以版本化 BOM 结构关联，是对业界 20 年实践共识的继承。

### 3.4 受控变更（Change under Control，遵循 CMII 思想）

业界标准变更链路：**问题报告（PR）→ 变更请求（ECR）→ 变更评审 → 变更指令（ECO/ECN）→ 执行与断点管理**。核心规则：
- 已发布（Released）对象**不可直接修改**，只能通过变更单走流程升级版本；
- 变更前必须做**影响分析**（被哪些 BOM 引用、影响哪些在制订单/库存断点）；
- 变更后自动**联编联动**（图纸、BOM、工艺、文档同步升版）并**通知下游**（ERP/MES/采购）。

### 3.5 流程与数据分离

流程引擎只负责"审批路由 + 任务 + 电子签名 + 状态推进"，不吞业务逻辑；业务规则（如"发布必填测试报告"）以可配置的**检查单/门禁规则**挂接到流程节点。好处：流程可随时重编、规则可独立演进——支撑敏捷承诺 A4。

### 3.6 配置优先于代码（Agile by Configuration）

借鉴开目"快速见效"打法与 Aras"模型驱动"架构，形成三级扩展金字塔：
1. **配置**（90% 场景）：类型/属性/表单/编码/生命周期/流程/报表/权限，全部界面化配置，热生效；
2. **声明式插件**（9% 场景）：业务钩子（校验器、派生属性计算、事件处理器）以 WASM/Rust 插件或脚本（如 rhai/JS）挂载；
3. **开放 API**（1% 场景）：任何能力皆 API，外部系统自由组装。

### 3.7 开放集成（Integration-First）

PLM 是研发数据源头而非孤岛：对上接 CAD/EDA 工具，对下接 ERP/MES/WMS/OA/IM（钉钉/企微/飞书）。本产品把"事件 + API + 连接器"作为一等功能：任何对象的新建/升版/发布/变更均产生事件，可供 Webhook 订阅。

### 3.8 工程理念：为什么是 Rust

| 传统 PLM 技术栈痛点 | RustPLM 对策 |
|---|---|
| JVM/中间件层层堆叠，部署重、内存高 | 单二进制 + tokio 异步运行时，无 GC、常驻内存低 |
| 大 BOM/批量操作卡顿、超时 | 零成本抽象 + 并发安全（所有权模型）保证数据竞争在编译期消除 |
| 升级停机窗口长 | 健康检查 + 滚动升级 + 数据库迁移框架（sqlx migrate） |
| 安全漏洞频出（内存安全类 CVE） | Rust 内存安全从根上消除整类漏洞，满足等保要求事半功倍 |

> Rust 不是噱头，而是"高效"卖点 F1–F5 的直接来源，并与"敏捷"承诺 A1/A3 的低运维成本互为因果。

### 3.9 中小微企业流程优化原则（SMB-First）★

传统 PLM 是为"有标准化部门、有多级审批、有专职 IT"的中大型企业设计的；直接卖给小微必然"流程比业务重"。本产品所有流程类功能必须遵循以下六条原则，并在默认模板中落地：

| # | 原则 | 含义与默认落地 |
|---|---|---|
| SMB-1 | **默认可用（Convention over Configuration）** | 装好即含：5 类角色权限包、简化版审批流（设计→总工→发布，3 节点封顶）、推荐编码规则、常用物料分类——小微客户**零配置开始使用**，而非从白纸开始 |
| SMB-2 | **流程分级（轻流程优先）** | 每类流程对象提供"极简/标准/严格"三档模板：极简（单人审批+留痕）、标准（2–3 级）、严格（会签+影响分析，用于成长后）。客户随规模切换，数据无需迁移 |
| SMB-3 | **一人多角** | 审批链自动跳过"审批人=发起人"的节点（可配置为留痕自审）；同一人多角色时界面按"当前身份"聚合待办 |
| SMB-4 | **移动优先审批** | 所有审批场景必须能在钉钉/企微/飞书卡片内完成（≤2 次点击），PC 只是补充 |
| SMB-5 | **快通道常态化** | 笔误类快速变更通道（EC-09）默认开启；急件模式：老板 IM 卡片"一键特批"，事后补正式记录 |
| SMB-6 | **不做时间线绑架** | 项目管理默认"轻项目"（任务清单+交付物+截止日），甘特/关键路径/资源负荷为可选增强——小微用不起重型 PMO 方法论 |

> 落地要求：以上原则作为需求评审检查单——任何新功能若导致"小微用户必须先理解中大型企业概念才能使用"，则该功能默认关闭或后移至成长模式。

## 4. 关键用户场景（Story 驱动）

### 场景 S1：图纸集中受控（替换共享盘）
设计员在中望 3D 完成设计 → 在 CAD 端一键"检入"→ 系统自动提取图纸属性（图号/名称/材料/比例）生成图文档对象并自动编号 → 图纸版本 A.1 → 提交流程 → 主管与标准化在线圈阅、电子签名 → 发布后自动转 PDF+水印归档，共享盘从此废弃。
**验收锚点**：CAD 检入不改变设计员习惯（≤3 次点击）；圈阅留痕可审计。

### 场景 S2：一物一码（物料申请与查重）
采购件新物料申请 → 表单填写 → 系统按"名称+规格+材料"智能查重并展示相似件（含 3D 预览）→ 标准化审批 → 自动按编码规则赋码（分类码+属性码+流水号）→ 同步创建 ERP 物料档案（若有集成）。
**验收锚点**：查重准确率（同物料被拦截）≥ 95%；赋码零人工干预。

### 场景 S3：EBOM→MBOM 演进与发布
结构工程师基于 CAD 装配体生成 EBOM → 工艺工程师派生 PBOM（合件/拆件/虚拟件调整）→ 生成 MBOM 关联工序与工时 → MBOM 发布流程 → 发布后自动推送 ERP 制造 BOM 与工艺路线 → ERP 返回接收回执。
**验收锚点**：多视图间可双向追溯（点任一 MBOM 行可回溯 EBOM 来源行）；10 万行 BOM 展开不卡顿（F1）。

### 场景 S4：一次受控变更（CMII 闭环）
车间发现图纸错误 → 提问题报告（PR）→ 评审立项 → ECR 提出更改方案 → 系统自动影响分析（引用该件的全部 BOM/在制订单/库存）→ ECO 批准 → 相关图纸、BOM、工艺文件**自动预升版并锁定**→ 执行完成 → ECN 通知采购/生产/ERP → 断点切换（旧版在某批次起停用，新版自某批次生效）。
**验收锚点**：全链路对象可双向追溯，审计报告一键导出。

### 场景 S5：7 天上线（敏捷实施；Starter 模式 1 天自助）
- **Starter 路径（≤20 人）**：技术负责人在任意一台有 Docker 的主机上执行一条 `docker compose up -d` → 等 10 分钟 → 浏览器进入首启向导（选行业→设管理员→扫码绑定钉钉/企微）→ 当天可用，历史图纸用 AI OCR 批量补属性；**全程不需要顾问、不需要会装数据库**；
- **标准路径**：实施顾问携带"非标自动化行业包"进场 → Day1 装 Docker/单机、导模板 → Day2 配组织与权限 → Day3 导入历史图纸（批量工具+AI OCR）与物料 → Day4 编码规则与表单微调 → Day5 流程编排（拖拽/选三档模板）→ Day6 试运行与培训 → Day7 切换正式库。全程**零后端代码**。
**验收锚点**：以实施清单（Checklist）逐项打钩交付；Starter 路径无顾问介入。

### 场景 S6：移动审批（IM 卡片 / 小程序，钉钉·企微·飞书·微信）
老板出差途中收到企微卡片"您有 3 个待审图纸"→ 点开查看图纸 PDF 与圈阅 → 一键同意 + 手写签名 → 流程自动推进；若开通 OA 集成，审批动作自动回写 OA 待办已办。老板只用微信？→ 微信小程序"待办"同样完成全流程；钉钉用户在工作台直接打开钉钉小程序办理。
**验收锚点**：移动审批闭环 ≤ 30s；IM 卡片与小程序双路径体验一致（同一待办任一端处理后其余端自动消失）。

### 场景 S7：FA 商城选型直连（买得对、买得快）★
机械工程师设计非标设备需选一批标准件 → 在 PLM 内嵌的"选型中心"搜索"怡合达 轴承座 UCP205"→ 展示结构化参数、3D 预览、规格书 PDF、参考价 → 一键"选型入库"：自动创建外购物料（型号/品牌/规格属性齐全）+ 下载 3D 模型挂到物料 → 工程师在 CAD 中直接引用 → 采购点击"去商城购买"直达怡合达/嘉立创/米思米下单页（带型号参数）。
**验收锚点**：从搜索到物料入库 ≤ 1 分钟、≤ 3 次点击；入库物料属性零手工录入；下单链接直达正确型号。

### 场景 S8：AI 研发助手（上线加速器 + 日常提效）★
- **迁移加速**：存量 5000 张 DWG 老图纸批量入库 → AI OCR 提取标题栏（图号/名称/材料/比例/数量）→ 自动填属性、自动分类、低置信度进入人工确认队列 → 一周完成过去一个月的整理工作；
- **日常提效**：工程师自然语言搜"去年那台贴片机的 Z 轴模组用了哪几家导轨"→ AI 基于全库检索生成带引用链接的答案；Excel BOM 导入时 AI 智能映射列名并清洗（单位/数量/型号纠错）；新员工问"公司外壳喷塑件公差标注规范"→ AI 从企业规范库 RAG 回答并给出文档原文位置。
**验收锚点**：OCR 提取准确率 ≥ 95%（标题栏字段级）；AI 回答必须附可点击的数据来源（防幻觉）；可配置"纯内网模式"（本地模型，数据不出厂）。

### 场景 S9：插件扩展（生态生长）
客户使用的国产 ERP 无预置连接器 → 合作伙伴用官方插件 SDK（Rust/TS）开发"XX-ERP 连接器插件"→ 打包上传插件市场 → 客户管理员一键安装 → 物料发布自动同步该 ERP。全程不动核心代码，升级不破坏。
**验收锚点**：插件安装/卸载不重启服务；插件崩溃不影响主进程（沙箱隔离）；提供插件调试与日志界面。

## 6. 功能需求详述

> 编号规则：`模块-序号`。优先级：P0 必须 / P1 重要 / P2 增强。

### 6.1 ORG 组织与权限管理

**目标**：支撑多部门/多角色/多工厂的组织建模，实现"功能权限 + 数据权限"双维度管控。

| 编号 | 需求 | 优先级 |
|---|---|---|
| ORG-01 | 组织建模：公司→部门→工作组→岗位→用户的多级组织树，支持一人多岗、跨部门兼职、汇报线与审批线分离 | P0 |
| ORG-02 | 角色管理：系统角色（见 1.4）+ 自定义角色；角色可继承；用户-角色-组织三维授权 | P0 |
| ORG-03 | 功能权限：按模块/菜单/按钮粒度授权（查看/新建/编辑/删除/导出/审批…） | P0 |
| ORG-04 | 数据权限：按对象类型配置维度规则——按组织、按项目、按密级、按分类、按状态（如：仅本部门草稿可编辑、全公司发布件只读） | P0 |
| ORG-05 | 密级管理：公开/内部/秘密/机密四级，密级权限矩阵控制可见与下载 | P0 |
| ORG-06 | 出差代理：审批任务可委托代理人，委托有起止时间与审计记录（对标华天/Teamcenter 标配） | P1 |
| ORG-07 | 用户生命周期：入职/转岗/离职冻结；离职用户数据与待办强制转移流程 | P0 |
| ORG-08 | 认证：本地账密（bcrypt/argon2）+ LDAP/AD 对接 + 企业微信/钉钉扫码登录（OAuth2）；双因素登录可开关 | P0/P1 |
| ORG-09 | 团队（Team）机制：项目团队/产品线团队动态组建，授权随成员变化即时生效 | P1 |

**验收要点**：权限判断在服务端统一网关完成（前端仅做显示裁剪）；权限变更 3s 内生效；全量权限决策延迟 < 5ms。

### 6.2 COD 编码系统

**目标**：为物料、图文档、BOM、变更单、项目等对象提供可配置的自动编码，落实"一物一码"。

| 编号 | 需求 | 优先级 |
|---|---|---|
| COD-01 | 编码规则引擎：码段组成可拼装——固定字符/属性映射码（分类或属性取值）/日期码/流水码/校验码；段序与长度可配；示例实时预览 | P0 |
| COD-02 | 流水号管理：按规则独立流水、可设断号重用策略、并发取号无重号（数据库行锁 + 缓存段双保险） | P0 |
| COD-03 | 一码多规则：不同对象类型/不同分类绑定不同规则（如标准件、自制件、图文档各有规则） | P0 |
| COD-04 | 编码唯一性校验：赋码接口幂等；外部导入批量查重 | P0 |
| COD-05 | 历史编码兼容：支持"旧码导入 + 新码规则并行"，映射表自动维护（保护存量数据迁移） | P0 |
| COD-06 | 规则变更受控：已用规则不可删除，停用需审批并留痕 | P1 |

### 6.3 PART 物料/零部件主数据

**目标**：建立企业级零部件主数据中心（一物一码、分类管理、查重、优选复用），成为 ERP 的数据源头。

| 编号 | 需求 | 优先级 |
|---|---|---|
| PART-01 | 物料类型：自制件/外购件/标准件/辅料/虚拟件等类型模板，各类型独立属性集 | P0 |
| PART-02 | 分类库（Classification）：多级分类树（如 GB/行业标准分类），分类挂属性模板与编码规则；分类可配置生命周期 | P0 |
| PART-03 | 属性管理：文本/数值/日期/布尔/枚举/单位量纲/多值/引用型属性；必填、正则、单位换算、默认值、公式派生属性（如"体积=长×宽×高"） | P0 |
| PART-04 | 物料申请-审批-发布流程模板（含标准化审查环节） | P0 |
| PART-05 | 智能查重：新建/导入时按名称/规格/材料/型号模糊+语义相似检索相似件，展示相似度与被引用次数；"申请新料必须先过查重"可配置为强制门禁 | P0 |
| PART-06 | 优选库/禁用库：零部件打标（优选、限选、禁用、停产），设计端 CAD/EBOM 引用时实时提示（对标 Windchill 重复件识别） | P1 |
| PART-07 | 物料与图文档/BOM/供应商的多维关联视图：一处查看该料全部图纸、被引用位置、库存参考（集成时） | P0 |
| PART-08 | 批量导入导出：Excel 模板化导入（校验错误行内定位提示）、增量更新、导入任务异步化并支持断点续传 | P0 |
| PART-09 | ERP 同步：发布物料经映射推送 ERP（用友 U9C/金蝶云星空/SAP 预置映射模板），失败重试与对账报表 | P1 |
| PART-10 | 零部件族与参数化族表（同族不同规格一表管理，类似 Family Table） | P2 |

### 6.4 DOC 图文档管理

**目标**：替换共享盘/FTP，实现图纸与技术文件的受控存储、版本管理、在线审签与圈阅。

| 编号 | 需求 | 优先级 |
|---|---|---|
| DOC-01 | 文档类型库：2D 图纸/3D 模型/技术协议/计算书/测试报告/规范标准等类型，各配属性、编码规则、默认流程 | P0 |

### 6.18 PLUGIN 插件化开发平台 ★

**目标**：让产品能力可以被安全地"外挂"生长——合作伙伴/客户 IT 用官方 SDK 扩展连接器、自动化、界面与算法，核心零改动、升级零破坏。这是"敏捷"从配置（AGL，改数据）迈向生态（PLUGIN，加代码）的第二级火箭。

#### 6.18.1 插件类型与运行机制

| 类型 | 运行位置 | 技术形态 | 典型用途 |
|---|---|---|---|
| 后端插件 | 服务进程内沙箱 | **WASM 组件（wasmtime）**，默认 Rust/AssemblyScript/Go 编译目标 | 业务钩子（校验/派生属性）、事件处理器、专有报表算子 |
| 连接器插件 | 服务进程内/旁路进程 | Rust trait `Connector`（动态加载 .so/.dll）或 WASM | 对接任意 ERP/MES/商城/设备（FA 模块与 INT 连接器均以此形态实现） |
| 前端插件 | 浏览器沙箱 | TypeScript + 官方 SDK（iframe/微件容器 + 受控 API 桥） | 对象详情页扩展卡片、自定义列表页签、外链面板 |
| 脚本插件 | 服务端沙箱 | rhai/JS 脚本（AGL-07 的超集，可独立打包分发） | 轻量自动化、批处理 |
| CAD/EDA 插件 | 桌面端 | Tauri 端插件规范（各工具原生 SDK） | 扩展长尾设计工具（DES-08） |

| AI-14 | **智能查重增强**：PART-05 查重的语义相似（"内六角圆柱头螺钉 M8×30" vs "GB70 M8x30 不锈钢"识别为同物）与合并建议 | P1（V1.5） |
| AI-15 | **编码分类推荐**：新物料按名称/规格自动推荐分类与编码段，标准化员一键确认 | P1（V1.5） |
| AI-16 | **变更影响摘要**：ECO 影响分析结果（EC-03）生成人话摘要与风险提示，供审批人快速决策 | P2（V2.0） |
| AI-17 | **文档起草辅助**：技术协议/变更说明/测试大纲初稿生成（基于对象数据），人工定稿 | P2（V2.0） |
| AI-18 | **BOM 工艺建议**（轻量）：外购/自制建议、常用搭配件推荐（基于历史 BOM 统计） | P2（V2.0） |

> 验收约束：所有 AI 输出在界面上明确标识"AI 生成/建议"；关键动作（入库/合并/发布）必须人工确认；AI 功能可整体禁用且不影响主流程（SYS-04 参数中心开关）。

## 7. 非功能需求（验收硬性基线）

### 7.1 性能（高效卖点的量化）

| 指标 | 目标值 | 测试条件 |
|---|---|---|
| BOM 全量展开 | 10 万行 < 1s（P95） | 单产品结构、含行属性 |
| 全文检索 | P95 < 200ms | 1000 万对象、关键词命中 1000 条 |
| 列表查询 | P95 < 300ms | 100 万级单表、常用筛选 |
| API 读/写延迟 | P95 < 100ms / < 300ms | 常规对象 CRUD |
| 并发用户 | 2C4G ≥ 50 并发（小微典型）；4C8G ≥ 300 并发 | 思考时间 10s 的典型操作流 |
| 流程流转 | 单节点 < 200ms；1 万在途实例无衰减 | — |
| CAD 批量检入 | 1000 张 DWG < 3min | 客户端与服务端同局域网 |
| 报表导出 | 10 万行 Excel < 30s | 服务端流式 |
| 文件上传 | 断点续传 + 内容寻址秒传 | — |
| 冷启动 | 服务进程 < 10s 就绪 | — |
| 页面体验 | 首屏 P95 < 1.5s；操作反馈 < 100ms | 内网千兆 |

### 7.2 可靠性与可用性

- 可用性 ≥ 99.9%（单机年停机 < 8.8h）；滚动升级不停机（双实例 + 反向代理摘流）；
- 数据安全：数据库 WAL + 每日全量备份 + 15 分钟增量（可配）；RPO ≤ 15min，RTO ≤ 1h；
- 事务一致性：对象+文件+索引三库写入采用"先落库、异步索引补偿"最终一致，提供对账修复任务；
- 数据库迁移全部走版本化迁移脚本，可前滚/回滚。

### 7.3 安全

- 传输 TLS 1.2+；密码 argon2id 存储；登录防爆破（锁定+验证码）；
- 越权防护：所有 API 服务端鉴权（对象级 ABAC 检查），防水平/垂直越权，安全测试用例全覆盖；
- 文件安全：病毒扫描钩子（ClamAV 可选）、危险格式隔离、下载全审计；
- 审计不可篡改（追加式 + 哈希链）；
- 合规目标：等保 2.0 三级技术要求对照表；可选包满足医疗（21 CFR Part 11 电子记录/签名类要求）。

### 7.4 易用性

- 界面语言：中文优先，术语统一（对齐 2.2 竞品通用术语，降低迁移学习成本）；
- 关键高频操作（检入、提交、审批）≤ 3 次点击；全局快捷键与命令面板（Ctrl+K）；
- 首次使用引导（场景化新手引导 + 内嵌帮助）；
- 无插件浏览（2D/3D 均浏览器原生渲染）。

### 7.5 可维护性与可扩展性

- 单二进制交付，版本升级 = 替换二进制 + 自动迁移；
- 日志：结构化（tracing），分级/采样/轮转，支持接入 ELK/Loki；
- 插件机制：WASM 脚本钩子（AGL-07）+ 外部事件（INT-02）两条扩展路径，不修改核心代码；
- 代码工程：核心域（对象/版本/流程/权限）与模块边界清晰（见技术架构文档），公共crate 复用。

### 7.6 部署形态



| 形态 | 说明 |
|---|---|
| **Docker 一键部署（小微推荐形态）** | 官方发布 `docker-compose.yaml` + 镜像（app + PostgreSQL 16，MinIO 可选）：**一条命令 `docker compose up -d` 完成**——自动拉起数据库、初始化、执行数据库迁移、健康检查通过后服务就绪；数据全部落命名卷（数据库/文件库/备份），删除容器不丢数据；首启 Web 向导（设管理员→选行业包→绑 IM）5 分钟内可用；升级 = `docker compose pull && docker compose up -d`，自动迁移、失败自动回滚镜像 |
| 单机包（无 Docker 环境） | 1 个可执行文件 + PostgreSQL + Systemd/service 脚本；**2C4G 起步（≤50 用户）**，一台入门服务器/工作站即可；安装向导 30 分钟就绪 |
| 离线内网包 | 全量离线安装介质（制造业内网常态）：单机版离线安装器 + **离线 Docker 镜像包**（`docker load` 导入，不依赖外网/镜像仓库）；含升级包与回滚脚本 |
| Kubernetes | Helm Chart，双副本滚动升级 + 对象存储；500+ 用户/高可用 |
| Starter 云托管（V2.0，可选） | 面向 3–20 人创客团队的官方轻量托管；数据可随时导出自部署（锁定解除承诺） |

> **Docker 一键部署验收标准（D-AC）**：
> 1. 全新 Linux 主机（含 Docker）从 `docker compose up -d` 到 Web 可登录 **≤ 10 分钟**（含镜像拉取）；
> 2. 应用镜像（多阶段构建、静态编译）**< 150MB**，2C4G 宿主机整机内存占用 < 3GB；
> 3. `docker compose down && up` 数据零丢失；备份卷独立可外挂；
> 4. 首启向导默认创建 Starter 模板（SMB-1），向导完成即可上传图纸；
> 5. 升级全程 < 5 分钟，迁移失败自动回退到旧版本并告警；
> 6. 容器内置 HEALTHCHECK，异常自愈（重启策略）并推送 IM 告警（INT-04）。

### 7.7 质量保障与自动化测试（TQ）

**目标**：质量内建于 CI，而非靠人肉回归。E2E 以 Playwright 脚本为核心，复杂交互（canvas 拖拽/巨表/圈阅）以 Playwright 拖拽与坐标 API 实现。

| 编号 | 需求 | 优先级 |
|---|---|---|
| TQ-01 | 测试金字塔：core crate 单元测试行覆盖 ≥70%（cargo-nextest + cargo-mutants 抽样变异测试）；mod 层集成测试基于 testcontainers 真实 PG 18 容器，不 mock 数据库 | P0 |
| TQ-02 | API 契约测试：OpenAPI 快照对比（oasdiff），破坏性变更即 CI 失败 | P0 |
| TQ-03 | E2E 自动化：Playwright 脚本覆盖关键用户旅程（场景 S1–S9 与验收锚点逐条映射，覆盖率 100%）；复杂交互（流程设计器拖拽连线、图纸圈阅标注、BOM 10 万行表格虚拟滚动/行内编辑、表单显隐联动）以 Playwright 拖拽/坐标/keyboard API 实现，失败自动输出截图与 trace | P0 |
| TQ-04 | 稳定性治理：E2E 用例 flaky 率 <5%，flaky 用例看板跟踪 | P1 |
| TQ-05 | 视觉回归：关键页面（工作台/列表/表单/看板）像素基线对比，UI 变更须显式更新基线 | P1 |
| TQ-06 | 测试数据工厂：一键种子数据集（含 10 万行 BOM、百万图纸元数据模拟、三档流程样例），一键重置，E2E 共享同一数据集保证可复现 | P0 |
| TQ-07 | CI 分层门禁：PR 合并=单测+集成+契约（<10min）；每夜=E2E 全量+视觉回归+性能基准（V-1/V-2 程序）+变异抽样；发布分支=全量 | P0 |
| TQ-08 | 测试报告：每次流水线产出统一质量报告（覆盖率/flaky/性能曲线），失败归因自动分类（产品缺陷/用例问题/环境问题） | P1 |

> 注：本项目开发过程采用 **AI agent 视觉交互自测**（开发期工程实践，见 ADR-0019），不构成产品功能需求。

**验收锚点**：MVP 交付时 S1/S2/S5/S6 场景有可执行 E2E；任一版本发布的质量报告可追溯。
